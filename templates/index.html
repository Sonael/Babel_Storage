Protocol & CLI Reference

This interface and babel_storage.py share the same engine (BSP v6), so every action here has an identical CLI equivalent.

Actions ↔ CLI

Web actionCLI equivalent
Upload File upload <file> --metadata out.json.gz
Upload with “Sign metadata” upload … --privkey private.pem
Download (with Strict mode) download out.json.gz --output file --pubkey public.pem --strict
Verify (shield) verify-metadata out.json.gz --pubkey public.pem --strict
Verify one chunk (shield in Info) verify-chunk out.json.gz --index N --pubkey public.pem
Info / Export / Import metadata info out.json.gz · the --metadata file itself
Re-sign (in Info, when invalid) re-run upload … --privkey with the current key

Server Settings (gear icon)

Editable and saved to babel_config.json, applied immediately — no restart. Each has a CLI/env equivalent:

SettingWhat it doesCLI / env
Rate limit Delay between chunks on upload (0 disables). Be kind to libraryofbabel.info. upload --rate-limit · BABEL_RATE_LIMIT
Max upload size Largest file the web upload accepts. BABEL_MAX_FILE_SIZE (bytes)
Retries per chunk Attempts before a chunk transfer gives up. --max-retries · BABEL_MAX_RETRIES
Retry backoff Initial wait between retries, doubled each try. --retry-delay · BABEL_RETRY_DELAY
Strict by default Initial state of the Strict-mode toggle. --strict · BABEL_STRICT

Startup-only (not editable here): host, port, debug and key paths — set via BABEL_HOST, BABEL_PORT, BABEL_DEBUG, BABEL_PRIVATE_KEY, BABEL_PUBLIC_KEY.

Strict mode (RFC-0005)

Off: a chunk whose SHA-256 does not match is reported as a warning and the restore continues. On: the restore aborts on the first integrity failure — chunk hash, final file hash, missing coordinates, chunk count, Merkle root, or an invalid signature.

Merkle verification (BSP v6)

Each file carries a Merkle root over its chunk hashes. The shield next to a chunk in Info proves that one chunk is authentic by fetching only it — no full download.

Signatures & keys

A signed badge means the signature verifies with the current public key; signature invalid means it does not — usually because the key was regenerated. Use Re-sign with current key in Info to fix it. Generate a key pair with the Generate RSA-4096 key pair button in Settings, or via the CLI: 

python -c "from crypto_utils import generate_keys; generate_keys('private.pem', 'public.pem')"

Resuming uploads

An interrupted upload leaves a partial metadata (shown as missing). From the CLI, re-run the same upload command to resume — already-uploaded chunks are skipped.
